## What is thin, and known

Written down rather than left to be discovered.

- **The visual mail editor uses `document.execCommand`.** It is deprecated and
  it is still the only thing that edits a selection inside a `contentEditable`
  without pulling in an editor framework. It works in Chromium, which is the
  only engine this app runs in. If it is ever removed, the code view is the
  fallback that still works.
- **The page editor is not Word, on purpose.** No text wrap around an image, no
  columns inside a flow, no style sheet. The block set is the set.
- **A box is dragged with a mouse or typed in millimetres.** There is no
  keyboard nudge yet. The inspector's number fields are the accessible path.
- **The walkthrough points at sidebar entries.** A stop whose target is missing
  falls back to a centred card, which is what happens if the sidebar is ever
  reshaped again.
- **Mail has still never met a real server.** Unchanged by this work, and still
  the most valuable thing left to do. See TODO.md.

## Second pass, the same month

Seven things, all asked for after looking at the first pass in the app.

- [x] **The first run is a window** (decision 34): 760 by 620, fixed, a modal
      child of the main window, so the app paints behind the questions. Its
      renderer entry is `#/setup` in the same bundle, the same trick settings
      uses. `main/windows/index.ts` now allows one modal child at a time and
      sends `window.childClosed` when either closes, which is what starts the
      walkthrough and picks up a replay.
- [x] **The questions were split.** A name step (first, last), then a business
      step (name, VAT number, establishment number). The eleven-field step is
      gone, and so are the email and phone questions.
- [x] **Email addresses and phone numbers are lists**, on the owner profile in
      `settings.json`, each entry an id, a value, a label and `isPrimary`, with
      exactly one primary settled by the service on every change. An address
      nobody reads is worth recording; the primary is what a document prints.
      `owner.contactName`, `owner.email` and `owner.phone` are derived in
      `shared/owner.ts` rather than stored again.
- [x] **Adding a mail account records its address** on the profile, without
      moving the primary, and Settings > Your business marks which addresses
      have an account of their own.
- [x] **Six MCP tools** for the two lists, because a capability the interface
      has and the agent does not is an unfinished feature.
- [x] **Mail with no account offers to connect one**, and the button opens the
      settings window on mail accounts. A section can ride in the window's URL
      now (`#/settings/mail`), or be sent to a window already open.
- [x] **The MCP tab is one choice with two routes**: let Juno write the file,
      or copy the entry. Codex and Antigravity joined the list, each row carries
      the product's mark, and detection answers two questions instead of one.

### What the second pass found

- **One flag cannot answer two questions.** "No configuration file yet" was
  true about the file and read as "Juno cannot find Claude", which is how an
  installed client with no MCP servers of its own came out looking absent.
  `installed` and `hasConfigFile` are separate now, and the row says which.
- **Codex is TOML.** The writer replaces `[mcp_servers.juno]` and its `env`
  table in place, keeps every other line byte for byte, and refuses a file that
  declares `mcp_servers` on one line rather than guessing. No dependency: one
  section of one format is smaller than the package that would parse all of it.
- **A step that embeds a settings section must not also have a title.** The
  lock step said "Lock" twice and stated the same warning twice, which is
  invisible in a full window and obvious in a 620px one.
- **Two modal children of one parent fight over focus**, and on Windows the
  loser is not reliably the one being looked at. Opening either closes the
  other, and setup reaches settings by handing over rather than stacking.
- **Reopening a window on the focus its own closing caused is a trap.** Setup is
  offered once per unanswered state, so closing it without answering leaves a
  usable app and asks again next launch.
- **The demo smoke run was inside ninety seconds and is now inside two
  minutes.** The old limit was marginal rather than generous, which showed up as
  a run killed mid-screenshot with nothing printed.
