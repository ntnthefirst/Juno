# Rework, September 2026

The work Nathan asked for after phases 0 to 6 were built and looked at. Eight
units, in dependency order. Each one is a commit or a small run of commits, and
each is verified with `npm run check` before the next one starts.

Keep this file honest. A unit is only ticked when it is built, checked and
looked at in both themes.

---

## 1. Navigation shell: a record opens full screen

- [ ] `src/app/breadcrumb.tsx`: a context the shell owns and a screen feeds.
- [ ] `TitleBar` renders `Juno / Screen / Record`, every segment but the last
      clickable.
- [ ] Clients: choosing a client replaces the list with the record, full width.
- [ ] Documents: the same.

Mail keeps its three panes and the calendar keeps its side panel, because both
are a row of something still being browsed (rule 5c, decision 30). Client
email, phone and address stay side panels for the same reason.

## 2. Mail templates and document templates are two screens

- [ ] `TemplatesScreen` split into `MailTemplatesScreen` and
      `DocumentTemplatesScreen`. One list each, no shared content pane.

## 3. Notes edit the way Obsidian does

- [ ] A live-styled Markdown editor: the styling is applied while typing, the
      markup is hidden until the cursor enters it.
- [ ] Used wherever notes are typed: clients, events, reminders, projects.

## 4. Mail template editor

- [ ] Preview a template from the list without opening the editor.
- [ ] A visual editor over the template HTML, with a code view for anyone who
      prefers it, and the preview updating as it is edited.
- [ ] Declared inputs on a template: name, label, type, required. Stored on the
      template, asked for when the template is used.
- [ ] Images: a URL or a file. A file becomes base64, which is the wrong answer
      in an email, so it asks first and says why.

## 5. Using a template is its own screen

- [ ] "Use" on a mail template: fill the inputs, link a client or no one,
      create the draft.
- [ ] "Use" on a document template: the same, ending in a PDF.

## 6. Document template editor: pages, not a textarea

- [ ] A page model: pages, a margin, and blocks inside it. Flowing blocks and
      absolutely placed boxes, like a PDF.
- [ ] Text, headings, images, spacers, page breaks, tables.
- [ ] Renders to the HTML the existing `printToPDF` pipeline already takes, so
      nothing below it changes.

## 7. A document is a PDF

- [ ] Import an existing PDF as a document.
- [ ] Generate from a template, which writes the PDF at generation.
- [ ] Open, review, sign, and the signed PDF is saved beside it.

## 8. First run

- [ ] A setup window on a genuinely empty install: welcome, your business,
      appearance, the lock, mail, done. Animated, and it degrades to nothing
      moving when the machine asks for that.
- [ ] A walkthrough of the app afterwards, replayable from Settings.
- [ ] `onboarding` in `settings.json`, so a reset or a clean install shows it
      again and a normal launch never does.
